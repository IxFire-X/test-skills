# context-marker — Разметка контекста

## Что это

Препроцессор мультиагентной системы тестирования. Принимает сырой `.md`-файл или произвольный текст без XML-разметки и оборачивает его в XML-теги согласно канону `CONTRACTS.md`, чтобы дальнейшие скиллы пайплайна (`tc-generator`, `tc-reviewer` и т.д.) могли работать с ним по контракту.

## Зачем нужен

В SDD-проектах аналитика часто лежит в виде обычных `.md`-файлов (требования, ADR, доменные описания) без какой-либо XML-разметки. Остальные скиллы пайплайна ожидают строгие теги (`<analytics_documentation>`, `<source_code_and_diff>` и т.д.). `context-marker` — мост между «сырыми» артефактами проекта и строгими контрактами системы.

## Как работает

Скилл поддерживает несколько режимов:

- **Прямой режим** (`analytics` / `source_code` / `test_cases` / `requirements` / `concept`) — оборачивает содержимое в явно указанный тег.
- **Автоопределение** (`auto`, режим по умолчанию) — анализирует ключевые слова в тексте и сам определяет тип контента.
- **Batch-режим** (`batch`) — сканирует всю директорию, размечает каждый `.md`-файл и выдаёт сводный отчёт.

## Контракт входа

| Тег | Обязательность | Описание |
|---|---|---|
| `<raw_content>` | Обязателен | Сырой текст / содержимое `.md`-файла |
| `<content_type>` | Опционально (по умолчанию `auto`) | Тип контента; при отсутствии — автоопределение |
| `<file_path>` | Опционально | Путь к файлу/директории (для batch-режима) |

## Место в пайплайне

Первый (опциональный) этап: `context-marker` → `tc-generator` → `tc-reviewer` → `tc-to-autotest` → `autotest-reviewer`. Вызывается автоматически Оркестратором при обнаружении нетегированной аналитики; при ручном запуске пайплайна — по явному промпту.
