# Документ по разделам, одним запросом

Когда `ready` напечатал `ВНИМАНИЕ` с прогонами или `submit plan` отказал `PLAN_REVIEW_TOO_LARGE`: прогоны из строки (её `fix`) веди по очереди сам, человека о каждом не спрашивай; прогон, на котором план отказал, дальше не веди.

1. Где мы — не по памяти: `python -m tools.assemble_sections --project <abs> --doc <документ>` читает журналы и по разделам называет `passed`, `no_csv` (с кодом) или `not_started`. Спрашивай её перед каждым прогоном и после сжатия контекста.
2. Прогон полный: `scan --docs "путь#Раздел" [--docs …]` → … → `finish` → `report`. Остальной документ — контекст: требования только из названных разделов, со строки вне них код отказывает.
3. Конец: `… --doc <документ> --write` — один CSV и сводка в `<последний прогон>/assembled/`; `not_started` — отказ, проведи прогон; `no_csv` в файл не идёт. Часть прогонов — `--run <id>` на каждый. Строка `without_case` («без кейса: п. 4.3.4 (SREQ-…, прогон 3 …)») значит: прогон `passed`, но у этого требования нет принятого кейса (например, ревью отклонило его кейс); перезапусти этот прогон с теми же `--docs` (новый заменит прежний целиком, `title_repeats` 0) или допиши кейс в CSV руками; назови человеку такие требования.
4. Человеку одной сводкой: по прогону исход ревью, принято из сгенерированного, поймано контрольных ошибок (слабое ревью — прямо), `no_csv` с кодом, `title_repeats`, путь к CSV. Следующий прогон начинаешь ты; код его не начинает.
