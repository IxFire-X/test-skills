## [2.0.1-lite] — 2026-07-09

> Синхронизация `SKILL-LITE.md` с изменениями полной версии `SKILL.md` v2.0.

### Добавлено
- **Frontmatter** — `name`, `version`, `description`, `triggers` (ранее отсутствовал). Триггеры синхронизированы с `SKILL.md`.
- **`execution_id`** в контракте выхода (UUID — сквозной trace ID).
- **Базовый Contract Check** в Шаге 1 — проверка имён корневых блоков и статус-маркеров по `CONTRACTS.md` §2/§3.
- **Таблица обязательных выходных тегов по скиллам** — компактная версия из `SKILL.md`.
- **Правило приоритета `<analytics_documentation>`** — аналитика как источник правды на всём протяжении пайплайна.
- **`failed` статус-маркер** в таблице решений (явная реакция на критическую ошибку).
- **Правила ветвления** при `AUTO_FIX_APPLIED` (`auto_fix: true` в отчёте) и запрет автоперезапуска при `ТРЕБУЕТ ДОРАБОТКИ`.
- **Декларативные правила retry** — транзитные (A, G, H, I) vs логические (B, D, J в strict-режиме).
- **Ссылка на `shared/sub-agent-compaction.md`** в секции изоляции контекста.
- `<analytics_documentation>` добавлен в правило изоляции контекста как сохраняемый артефакт.
- `input_contract` / `output_contract` в описании L1 Progressive Disclosure.

### Изменено
- **Fallback-таблица A–J** полностью пересинхронизирована с `SKILL.md` v2.0 (коды теперь совпадают по семантике).
- **Контракт выхода** — добавлены `version="2.0"`, `<execution_id>`, `<retries>` в `<step>`.
- **Шаг 1 алгоритма** — переименован в «Подготовка контекста + базовый Contract Check».
- **Шаг 2 алгоритма** — добавлена генерация `execution_id` (UUID).
- **Шаг 6 алгоритма** — отчёт теперь включает результат Contract Check.
- **Чеклист качества** — добавлены пункты: Contract Check, приоритет `<analytics_documentation>`.
- **Секция «Переход на полную версию»** — обновлён список ситуаций и возможностей полной версии.
- **Правило изоляции** — явно указан запрет передачи внутренних рассуждений (`<thought>`, `<analysis>`, `<draft>`, `<notes>`).

- Сохранены: диспетчеризация пайплайна, контроль итераций, изоляция контекста, обработка ошибок Fallback A–J.

## [2.0.0] — 2026-07-03

> Полное удаление documentation-pipeline. Единственный пайплайн — `test-pipeline`.

### Удалено
- **Пайплайн `documentation-pipeline`** и все связанные скиллы: `concept-analysis`, `docs-review`, `doc-fix`.
- **Пайплайн `review-pipeline`** — удалён вместе с `docs-review`.
- Статус-маркеры `production-ready`, `not-ready`, `fixed`, `partial-fixed` — перемещены в `CONTRACTS.md` §3.1 как `@deprecated` (сохранены только для чтения старых отчётов).

### Изменено
- **`version: 2.0`** во frontmatter `SKILL.md` (major — изменена структура пайплайна).
- **Единственный пайплайн:** `test-pipeline` (`context-marker → tc-generator → tc-reviewer → tc-to-autotest → autotest-reviewer`).
- **Триггеры** обновлены: удалены `"создай документацию"`, `"проверь документацию"`; добавлены `"создай тест-кейсы"`, `"сгенерируй автотесты"`, `"запусти тестовый пайплайн"`.
- **Contract Check** переработан под контракты тестового пайплайна (`CONTRACTS.md` §2/§3).
- **Таблица решений по статус-маркерам** переписана под вердикты `tc-reviewer` / `autotest-reviewer` (`ПРИНЯТО` / `AUTO_FIX_APPLIED` / `ТРЕБУЕТ ДОРАБОТКИ`).
- `README.md` и `examples.md` полностью переписаны под `test-pipeline` (устраняет расхождение, зафиксированное в аудите).

### Добавлено
- **Deep Scan (v1.3)** — полное сканирование проекта (код, документация, методология SDD/TDD/BDD) перед стартом пайплайна.
- **Zero-Config Mode (v1.2)** — автообнаружение стека при отсутствии `.skillsrc`.
- **Quickstart-режим (v1.2)** — триггеры `"инициализируй проект"`, `"quickstart"`, `"настрой проект"`.
- **Единый `<project_context>`** — блок, передаваемый всем скиллам пайплайна.
- **Progressive Disclosure (v1.4)** — двухфазная диспетчеризация L1 (метаданные `.skillsrc`) → L2 (полный `SKILL.md`).
- **Sub-Agent Spawn & Compaction** — ссылка на формальный протокол `shared/sub-agent-compaction.md`.
- **`context-marker`** — интеграция опционального препроцессора разметки сырых `.md`-файлов.

## [1.1.0] — 2026-07-03

> Унификация контрактов с `CONTRACTS.md` v1.0 по итогам аудита (`audit-report.md`).

### Изменено
- **Таблица «Обязательные выходные теги по скиллам»** приведена к канону `CONTRACTS.md` §2:
  - `autotest-reviewer`: `<review>` → `<autotest_review>` (корневой блок)
  - `concept-analysis`: `<documentation>` + `<status>` → `<analysis_result>` (содержит `<status>`, `<concept_document>`, `<completeness_score>`)
  - `docs-review`: `<review>` + `<review_verdict>` + `<review_comments>` + `<correction_plan>` → `<review_result>` (содержит `<status>`, `<correction_plan_path>`, `<summary>`, `<verdict>`)
  - `doc-fix`: `<documentation>` (обновлённая) + `<status>` → `<fix_result>` (содержит `<status>`, `<document_path>`, `<report_path>`, `<summary>`, `<verification_status>`)
- **Таблица решений по статус-маркерам:** удалён маркер `partial-ready` (дубль `partial`); `partial` теперь используется единообразно для `concept-analysis` и `docs-review`.
- **Контрактное версионирование:** неисполнимый SemVer для тегов **заменён** на исполнимый **Contract Check** (чеклист по `CONTRACTS.md` §5).
- **Retry / timeout / idempotency:** помечены как **декларативная спецификация** (аудит, рекомендация №6). Реальное исполнение зависит от LLM-провайдера / хоста.

### Добавлено
- **Contract Check** (Шаг 2 алгоритма + секция «Контрактное версионирование»): проверка имён корневых блоков и статус-маркеров перед стартом пайплайна. Результат фиксируется в начале `orchestration-report-<TS>.md`.
- **Секция «Ожидаемые пары»** в «Контрактном версионировании» — таблица допустимых пар (skill_N → skill_N+1).
- **Версионирование самого Оркестратора** (отдельно от контрактов): правила major/minor для SKILL.md Оркестратора.
- Ссылка на `CONTRACTS.md` в шапке файла.
- Примеры в §"Примеры использования" дополнены явной нотацией `Contract Check: PASS`.

### Устарело
- **SemVer для тегов** (`MAJOR.MINOR` каждого тега) — заменён на Contract Check. У тегов нет реальных версий, проверка была неисполнимой.

## Как использовать этот CHANGELOG

**Правила ведения:**
1. Новая версия — новая секция сверху.
2. Категории изменений: `Добавлено` / `Изменено` / `Устарело` / `Удалено` / `Исправлено` / `Безопасность`.
3. Версия в `CHANGELOG.md` должна совпадать с `version` в frontmatter `SKILL.md`.
4. Дата — ISO 8601 (`YYYY-MM-DD`).
