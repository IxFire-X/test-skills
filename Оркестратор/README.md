# Оркестратор (orchestrate)

Скилл для координации тестового пайплайна (`test-pipeline`) с контролем итераций, изоляцией контекста и обработкой ошибок.

## Когда использовать

- Нужно выполнить полный цикл генерации тест-кейсов и автотестов одной командой
- Требуется контроль качества на каждом этапе (Contract Check, Quality Gate)
- Необходима изоляция контекста между агентами (sub-agent spawn + compaction)
- Есть потребность в автоматическом retry при ошибках
- Нужно быстро инициализировать новый проект (Quickstart / Zero-Config)

## Вход

- Целевое действие (например, "создай тест-кейсы и автотесты для TransferService")
- Контекст проекта (опционально)

## Выход

- Финальный результат выполнения пайплайна (тест-кейсы, автотесты)
- Отчёт `docs/to_do/orchestration-report-<TIMESTAMP>.md` со статусами всех шагов

## Пайплайн

Единственный поддерживаемый пайплайн — `test-pipeline`:

```
context-marker (опц.) → tc-generator → tc-reviewer → tc-to-autotest → autotest-reviewer
```

`context-marker` вызывается автоматически, если аналитика проекта обнаружена в виде сырых `.md`-файлов без XML-разметки.

## Статус-маркеры

| Статус | Описание |
|--------|----------|
| `completed` | Все шаги пайплайна выполнены успешно |
| `partial` | Часть шагов выполнена (например, достигнут лимит итераций) |
| `failed` | Критическая ошибка при выполнении (в т.ч. `contract_mismatch`) |
| `retry` | Достигнут `max_iterations`, требуется вмешательство пользователя |

## Использование

```
Создай тест-кейсы и автотесты для TransferService
Запусти тестовый пайплайн для RenewalService
Сгенерируй тест-кейсы и проверь их
```

## Версии
