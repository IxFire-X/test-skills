# Камертон: быстрый старт

От подключения пакета до первых тест-кейсов — минут за пятнадцать. Первый прогон — только тест-кейсы и их ревью, без автотестов: так работает любая поставка. Подробности — [HOW-TO-USE.md](HOW-TO-USE.md).

## 1. Подключить пакет

Положите папку пакета в проект как `.tools/test-skills`. Нужен Python 3.11–3.13, больше ставить ничего не нужно.
Допишите в `.gitignore` проекта три строки: `.tools/`, `.pilot-runs/`, `.skillsrc*`.

## 2. Проверить пакет

Терминал — в папке `.tools/test-skills`:

```text
python -m tools.doctor --root .
```

`"status": "PASS"` — можно идти дальше. Иначе смотрите `messages`: обычно достаточно заново скопировать пакет.
`python` не находится — `py -3.11` (Windows) или `python3` (Linux).

## 3. Проверить изменение — секунды, без модели

Откройте программу с моделью в папке проекта и дайте запрос:

```text
Выполни .tools/test-skills/skills/orchestrate/SKILL.md.
Проверь изменение OpenSpec <имя>: только ready, кейсы не пиши.
```

Агент покажет таблицу готовности. `СТОП` — исправьте по подсказке рядом и повторите запрос.

## 4. Написать тест-кейсы

```text
Выполни .tools/test-skills/skills/orchestrate/SKILL.md.
Напиши тест-кейсы по изменению OpenSpec <имя>. Код (по желанию): <папка>
```

Кейсы пишутся только по требованиям изменения; смежные требования базы агент назовёт строкой «Проверьте регресс:». Обычный документ вместо изменения — «по документу docs/feature.md». Агент пишет кейсы, проводит их ревью и называет
пути к файлам. Если он спросит (исключить требование или продолжать, ревью в той же сессии) — ответьте. Работу прервали —
«продолжай test-skills <run_id>». Прогон агент ведёт сам, в основной сессии, а не в субагенте.

До первого шага модели от вас нужно от одного до пяти решений: какое изменение или документ, папка кода (по желанию). При первом запуске агент может спросить ещё: какой модуль, если их несколько; где код приложения, если модуль только с тестами (или «кода приложения нет»); в поставке с автотестами — имя переменной с адресом стенда.

## 5. Где результат

Всё — в `<проект>/.pilot-runs/<run_id>/`:

- `published/<документ>.r<ревизия>.zephyr-scale.csv` — кейсы для импорта в Zephyr (только у набора, принятого ревью);
- `published/<документ>.r<ревизия>.html` и `.md` — те же кейсы для чтения;
- `questions-for-analyst.md` — вопросы аналитику: пробелы и неясности требований;
- `report.md` — отчёт прогона.

Пользовательские поля Zephyr (АС, Команда…) у новых кейсов пустые: заполните их перед импортом или один раз задайте шаблон — HOW-TO-USE.md, раздел 6.

## Дальше

Когда какой запрос давать, обновление кейсов из Zephyr, частые остановки — [HOW-TO-USE.md](HOW-TO-USE.md).
