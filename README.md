# Трасса

**От требования до теста — по одной трассе.**

Трасса — набор инструкций для модели и Python-инструментов к ним. По документу требований к одной функции она
готовит тест-кейсы и отдаёт их на ревью. Код проекта, его сборку и тесты агент не запускает; если в поставке есть автотесты, их запускает человек.

Для кого: тестировщики и разработчики, которые работают в программе с доступом к модели (CLI компании или
похожей).

**Как начать — [HOW-TO-USE.md](HOW-TO-USE.md)**: подключение, проверка готовности, запрос для модели,
результаты, продолжение после перерыва и частые остановки.

## Что вы получаете

- **Тест-кейсы** — в HTML и Markdown для чтения и в JSON как исходный документ. Каждый кейс связан
  с требованием, из которого он вырос.
- **CSV для Zephyr Scale** — файл `<документ>.r<ревизия>.zephyr-scale.csv`, только у набора, принятого ревью; по шаблону
  выгрузки вашего проекта Трасса заполнит и CSV для импорта без ручных правок. Отклонённый набор — файлы `*.REJECTED.*`
  с замечаниями в шапке, без CSV.
- **Отчёт ревью** — приняты ли кейсы и что проверяющий потребовал исправить.
- **Отчёт прогона** — шаги, время, размеры входа модели, коды остановок; без кода проекта и текстов кейсов.
- **Вопросы аналитику** — `questions-for-analyst.md`: пробелы и неясности требований, найденные по дороге.

## Что происходит

Трасса читает документы и код проекта, пишет кейсы и проводит их ревью. Пишет она в проект только своё:
папку прогонов `.pilot-runs/`, файл настроек `.skillsrc` и каталог публикации `published/` с готовыми кейсами —
`.pilot-runs/<run_id>/published`. Ничего не устанавливает, не обращается к сети, не запускает сборку, тесты и git.
Режим автотестов (режим Б) входит в поставку профиля `mode-b`; в поставку `cases-only` он не входит. Профиль называет `doctor`.

## Что лучше иметь для гладкого запуска

- **Программу с доступом к модели**, которая умеет читать и писать файлы и выполнять команды. Лучше, если
  она умеет запускать проверяющего в отдельном контексте; если нет — ревью идёт в той же сессии.
- **Python 3.11–3.13.** Больше ничего ставить не нужно: сторонние пакеты и виртуальное окружение пакету не требуются.
- **Документы требований в UTF-8.**
- **Для импорта кейсов** — CSV-выгрузка Zephyr Scale (разделитель «,» или «;», UTF-8) или CSV Трассы
  профиля v5.

Если ваш CLI ругается на шапку файлов `SKILL.md` (блок `permissions` в начале), напишите разработчикам.

## Ревью без отдельной сессии

Ревью идёт в одной из двух веток. `INDEPENDENT` — отдельная чистая сессия (или субагент), свежий контекст обязателен. `SELF` — если
в вашем CLI её не открыть: ревью в той же сессии, новую открывать не нужно, результат не называется независимым. Это нормальный режим,
а не сбой: отчёт показывает пометку, а принимается такой результат только по вашему согласию (флаг `--accept-self-review` в `scan`).

## Чем всё закончилось

Главное — вердикт ревью кейсов. В прогоне только кейсов `verification=NOT_APPLICABLE` и `accepted=false` ожидаемы: запуска
автотестов нет, ревью кейсы при этом не отвергло.

## Если команду оборвали

Прогон восстанавливается после обрыва процесса: следующая команда доводит или откатывает незаконченную запись журнала. Крах
операционной системы и отключение питания не обещаются: после них журнал мог остаться неполным, тогда команда назовёт
`JOURNAL_CORRUPT` и поможет начать новый прогон. Команды одного прогона не запускайте параллельно — вторая подождёт первую, а если
та идёт слишком долго, ответит `CONCURRENT_WRITER`.

## Словарь терминов

| Слово | Что значит |
| --- | --- |
| прогон (run) | одна папка `.pilot-runs/<run_id>` в проекте: всё, что Трасса записала по вашему запросу |
| попытка (attempt) | один заход внутри прогона: кейсы и ревью; закрывается итогом |
| ревизия (revision) | версия документа: `r1` — первая, `r2` — после правок по ревью; третьей нет |
| ревью принято (accepted) | в этой поставке `false` по определению; главное — вердикт ревью |
| проверка (verification) | в прогоне только кейсов запуска нет: `NOT_APPLICABLE`; в режиме автотестов — результат запуска, сделанного человеком |
| покрытие (coverage) | автотесты создаются только в режиме автотестов; значение (`FULL`, `MIXED`, `MANUAL_ONLY`) справочное, на вердикт ревью не влияет |
| завершённость (completion) | `COMPLETE`, `PARTIAL` или `FATAL` (прогон не довели) |

## Для разработчиков пакета

В поставке — машинный контракт `contracts/pipeline.json` и его проекции `CONTRACTS.md` и `PIPELINE.md`. Справочник
разработчика, тесты и гейт пакета — только в репозитории разработчика.
