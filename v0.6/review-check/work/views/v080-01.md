## Исходные требования

- SREQ-0001: 1.1.1. Все операции предметной области доступны по префиксу `/petclinic/api` на порту 9966; запрос по пути контракта без этого префикса операцией API не обслуживается. Неподтверждённое условие: контракт задаёт префикс только в адресе сервера и не описывает ответ на запрос без него; ожидаем 404.
- SREQ-0006: 1.2.1. Ответ с кодом 200 на запросы `GET` по всем адресам списков и чтения одной записи содержит заголовок `ETag` с непустым значением (контракт описывает его в каждом таком ответе).
- SREQ-0016: 2.1.1. Каждое из пяти полей `OwnerFields` обязательно. Если поле отсутствует в теле, равно `null` или равно пустой строке, а остальные четыре поля корректны, `POST /owners` возвращает 400 с телом `ProblemDetail`, и новый владелец не создаётся.
- SREQ-0017: 2.1.2. Значение firstName длиной 30 символов (30 букв A) принимается, длиной 31 символ отклоняется ответом 400. Значения длины 1 («A») принимаются.
- SREQ-0018: 2.1.3. firstName состоит из одного, двух или трёх слов из букв (в том числе нелатинских), разделённых одним пробелом, апострофом или дефисом. Принимаются: Irina, Anna-Maria, Jean Paul, O'Neil, Élodie, Иван. Отклоняются ответом 400: Anna1, «Anna  Maria» (два пробела подряд), «␣Anna» (пробел в начале), Anna- (разделитель в конце), A-B-C-D (четыре слова), Anna. (точка в конце).
- SREQ-0021: 2.1.6. address принимает значения длиной от 1 до 255 символов: строка из 255 букв B принимается, из 256 — отклоняется ответом 400. Содержимое адреса (цифры, точки, запятые, пробелы) шаблоном не ограничено.
- SREQ-0026: 2.2.2. В теле ответа на создание `id` — целое число не меньше 0, выданное сервером, а `pets` — пустой массив. Повторный запрос `GET /owners/{id}` возвращает те же значения.
- SREQ-0030: 2.2.6. Запрос `POST /owners` с телом, не являющимся корректным JSON (например, `{"firstName": `), возвращает 400 с телом `ProblemDetail`. Неподтверждённое условие: контракт описывает 400 как «Bad request» без перечня причин.
- SREQ-0033: 2.3.3. `GET /owners/{ownerId}` для несуществующего идентификатора возвращает 404 с `ProblemDetail`; данные других владельцев в ответ не попадают.
- SREQ-0034: 2.3.4. Идентификатор 0 лежит в допустимых границах контракта: запрос `GET /owners/0` возвращает 404 (владельца с таким id нет) или 200 (если он есть), но не 400.
- SREQ-0049: 2.6.2. После обновления питомцы владельца и их визиты сохраняются: массив `pets` в повторном `GET /owners/{ownerId}` содержит тех же питомцев с теми же визитами. Количество владельцев в `GET /owners` не меняется.
- SREQ-0058: 3.1.4. Поле birthDate в схеме снабжено проверкой возраста питомца (`PetAgeValidation`). Неподтверждённое условие: содержание проверки в контракте не описано; ожидаем, что дата рождения позже D (в будущем) отклоняется ответом 400, а дата D принимается.
- SREQ-0064: 3.3.1. `GET /owners/{ownerId}/pets/{petId}` для питомца этого владельца возвращает 200 и `Pet` с полями name, birthDate, type, id, ownerId, visits.
- SREQ-0071: 4.1.1. description обязателен: отсутствие, `null` и пустая строка отклоняются ответом 400 с `ProblemDetail`, визит не создаётся. Строка из 255 букв принимается, из 256 — отклоняется ответом 400.
- SREQ-0089: 5.1.3. `GET /v2/pets?page=0&size=2` возвращает не более двух элементов; `size` в ответе равен 2, `totalPages` равен частному от деления `totalElements` на 2 с округлением вверх.
- SREQ-0105: 7.1.3. name обязателен и ограничен длиной: отсутствие, `null` и пустая строка отклоняются ответом 400 с `ProblemDetail`; строка из 80 букв принимается, из 81 — отклоняется ответом 400. Справочник после отказа не меняется.
- SREQ-0107: 7.1.5. `PUT /specialties/{specialtyId}` с телом `{"id": <тот же id>, "name": "dentistry-updated"}` возвращает 200 и обновлённую `Specialty` с прежним `id`; для несуществующего идентификатора возвращается 404, для name из 81 символа — 400.
- SREQ-0121: 10.1.2. При нарушении правил полей запроса (например, firstName из 31 символа) ответ — 400, а массив schemaValidationErrors содержит не меньше одного элемента, у каждого элемента есть строковое поле message с непустым значением.
- SREQ-0126: 11.1.2. При включённой аутентификации запрос без заголовка `Authorization` или с неверным паролем отклоняется ответом 401; запрос `admin`/`admin` выполняется для операций всех разделов этого документа.
