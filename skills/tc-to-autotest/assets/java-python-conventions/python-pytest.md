# Необязательные соглашения Python/pytest для нового рабочего пространства

Использовать только тогда, когда пользователь выбрал Python/pytest, а в проекте нет существующего тестового шаблона.

- Pytest, стабильное имя, маркер или ID параметра с `TC-*`.
- Выбрать синхронный или асинхронный клиент согласно рабочему интерфейсу; не навязывать `httpx`.
- Создавать фикстуру, только когда она нужна нескольким тестам и её данные не являются секретами.
- Передавать параметры окружения и аутентификации через подтверждённый механизм времени выполнения.
- Проверять каждый ожидаемый результат отдельной читаемой проверкой с диагностическим контекстом.
- Создавать только новые тестовые файлы и не менять рабочий код, конфигурацию или зависимости.
