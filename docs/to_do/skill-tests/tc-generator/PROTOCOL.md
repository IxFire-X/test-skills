## Adaptive evaluator gate

Initial-GREEN and FINAL-GREEN use cumulative sequential checkpoints `1 -> 3 -> 5`: run `rep-01`; only after protocol + schema + campaign semantic checker all succeed run `rep-02` and `rep-03` sequentially; only after the three-run checkpoint is accepted run `rep-04` and `rep-05` sequentially. The completed tc-generator RED-v2 diagnostic prefix is explicitly `rep-01..03`; its terminal `rep-04` failure was controller-caused and does not authorize `rep-05`, retry, repair, or RED-v3. Schema validation runs before semantic validation for every repetition. The first nonzero protocol/schema/semantic result stops the batch immediately. Preserve that exact repetition and its evidence immutable; mark/exclude it as invalidated/unscored where the evidence schema permits, and never replace, repair, overwrite, or restart it.

Five independent successful repetitions are required for comparable completed phase scorecards; the one- and three-run checkpoints only control expansion. Pressure remains one separate adversarial run after initial GREEN and obeys the same immediate-stop/no-rerun rule.

While status is pending, retain every successful tc-generator run as an ordered contiguous successful prefix of RED-v2 `rep-01..03`, effective initial GREEN `02-green-initial-v3/rep-01..05`, pressure, then effective FINAL-GREEN `rep-01..05`. ## Literal command evidence contract v1

`00-scenario.json` sets `protocol_contract_version: 1`. On every future active tc-generator run — RED, initial GREEN, pressure, and effective FINAL-GREEN — append one `commands` entry for every command actually executed, in execution order. Each entry must contain exactly `id`, `argv`, `cwd`, and `exit_code`; `argv` is the literal argument array, never a shell string, and `cwd` is the absolute campaign root. The same ordered entries must be in both `06-run-metadata.json` and that run's `run-protocol.json`.

For every scorable tc-generator run, every recorded command exits `0`. The exact canonical `tools/validate_artifact.py` attempt occurs once, with `id: "validate-artifact"`, exactly four absolute argv values (the actual absolute evaluator/controller Python executable, `tools/validate_artifact.py`, `schemas/tc-generator-output.schema.json`, and that run's exact reserved `tc-generator-output.json`), and exit code `0`. It is immediately followed by the final `semantic-check` command: `[<the-identical-absolute-python>, <absolute-campaign>/check_output.py, "--input", <absolute-campaign>/artifacts/inputs/context-marker-output.json, "--output", <exact-absolute-reserved-output>, "--mode", "red-control"|"canonical"|"pressure"]`; its cwd is the absolute campaign root and its exit code is `0` for scorable evidence. Normal phases target `artifacts/outputs/<phase>/<rep>/tc-generator-output.json`; RED uses `red-control` mode, and active effective pressure `03-pressure-v4` targets `artifacts/outputs/03-pressure-v4/pressure/tc-generator-output.json` with `pressure` mode. `03-pressure-v3` is the immutable/unscored fork-turns-mismatch archive: its recorded bytes are evidence only and are never an active validator, semantic, or evaluator target.

A RED checker payload may report `gap` while its `semantic-check` exit code is `0`; that is scored RED evidence, not invalidation. A nonzero protocol, schema, or semantic command means no valid/scorable observation was produced and stops the batch under the adaptive gate. Preserve the first failed repetition immutable in the invalidated/unscored ledger with its literal `commands`, `started_at`, `finished_at`, nested `evaluator`, `task`, immutable prompt/observation/output SHA-256 evidence, and `protocol_snapshot`; the snapshot repeats the same prompt hash, timing, evaluator, task, observation/output paths, and command array. The first nonzero command is the last executed command. A pre-validator protocol/evaluator failure has neither validator nor semantic command; a failed schema validator is last and has no semantic command; a failed semantic check follows one successful sole validator. The bounded `03-pressure-v2` exception is an unspawned `read-prompt`: preserve only its four successful controller commands plus diagnostic `{process_created:false, exit_code:null, windows_api:"CreateProcessAsUserW", win32_error:5}`; do not record that attempted read as a command, output, validator, semantic check, reserved output, or `checked_output`. Validator or semantic invalidations additionally preserve the actual reserved output targeted by validator argv and a byte-identical SHA-256 archived `checked_output` under `artifacts/invalidated`; the run protocol lists that actual reserved output alongside diagnostic output paths. A pre-validator failure still preserves prompt, protocol, observation, and at least one honest diagnostic output, but has no `checked_output`. Never replace, repair, overwrite, restart, or silently reuse that repetition; recovery requires an explicit new versioned phase or plan change. Record no synthesized or reconstructed commands. Existing historical evidence without v1 literal command capture remains unchanged.
