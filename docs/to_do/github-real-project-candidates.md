# Ранжированный список реальных GitHub-проектов для кампаний portable testing skills

Срез исследования: **2026-08-10**. Это подбор кандидатов, а не свидетельство установки или тестирования какого-либо проекта. InvenTree и `step5-java-demo` намеренно исключены.

Ниже использованы только первичные источники проектов: официальные GitHub-репозитории, файлы репозиториев, страницы релизов, определения API и файлы лицензий. Рейтинг и оценки сложности запуска — выводы для нашей программы проверки скиллов, а не заявления самих проектов. Приоритет отдан детерминированным срезам API, полезным сценариям авторизации, валидации и переходов состояния, практичному локальному запуску на Windows, свежей поддержке и убедительному маршруту от `context-marker` до полной оркестрации.

## Основные кандидаты

### 1. PocketBase

- **Repository, stack, license, activity.** [PocketBase](https://github.com/pocketbase/pocketbase) is a Go backend that bundles an embedded SQLite database, realtime subscriptions, file and user management, an admin dashboard, and an HTTP API. Its [license is MIT](https://github.com/pocketbase/pocketbase/blob/master/LICENSE.md). The latest stable evidence selected for this survey is [v0.38.2, released 2026-05-22](https://github.com/pocketbase/pocketbase/releases/tag/v0.38.2).
- **Exact testable slice.** The official record router defines `GET /collections/{collection}/records`, `GET /collections/{collection}/records/{id}`, `POST /collections/{collection}/records`, `PATCH /collections/{collection}/records/{id}`, and `DELETE /collections/{collection}/records/{id}` in [`apis/record_crud.go`](https://github.com/pocketbase/pocketbase/blob/master/apis/record_crud.go#L53-L60). Password authentication, refresh, OAuth2, OTP, and impersonation routes are defined in [`apis/record_auth.go`](https://github.com/pocketbase/pocketbase/blob/master/apis/record_auth.go#L31-L54). The bounded campaign slice should use password auth and one custom `tasks` collection, not every authentication mode.
- **Pipeline fit — assessment.** `context-marker` must extract schema, required fields, ownership rules, filters, and auth preconditions from both prose and Go routes. `tc-generator` can derive CRUD, duplicate/invalid-field, unauthenticated, cross-user, filter, and state-change cases. `tc-reviewer` has clear omissions to catch: missing rule coverage, weak status/body oracles, absent cleanup, and user-token leakage. A later auto-test-writer/reviewer can produce compact HTTP tests against deterministic record IDs and bodies; full orchestration adds one executable, readiness polling, admin/collection seeding, isolated data, and teardown.
- **Windows setup and dependencies — Low.** The [README documents downloading a prebuilt executable and running `pocketbase serve`](https://github.com/pocketbase/pocketbase#how-to-use), while [release assets include Windows builds](https://github.com/pocketbase/pocketbase/releases/tag/v0.38.2); the embedded database removes the need for a separate database service. Building from source instead requires the Go version stated in the [README](https://github.com/pocketbase/pocketbase#building-and-running-the-repository).
- **Proposed chain.** Bootstrap a local superuser; create a `tasks` collection with required `title`, enum-like `status`, and owner-only list/view/update/delete rules; create users A and B; authenticate A; create, filter, update, and delete A's task; prove B cannot read or mutate it; finally remove users and collection.
- **Caveat.** The project [warns that full backward compatibility is not guaranteed before v1.0](https://github.com/pocketbase/pocketbase#please-note), so a campaign must pin v0.38.2 rather than `latest`.

### 2. Spring PetClinic REST

- **Repository, stack, license, activity.** [Spring PetClinic REST](https://github.com/spring-petclinic/spring-petclinic-rest) is a Java/Spring Boot REST backend with an OAS 3.1 document and generated API types. Its [license is Apache-2.0](https://github.com/spring-petclinic/spring-petclinic-rest/blob/master/LICENSE.txt). Its official [commit history records Spring Boot 4.1.0 and OpenAPI Generator 7.23.0 updates on 2026-07-02, plus pagination work in June 2026](https://github.com/spring-petclinic/spring-petclinic-rest/commits/master).
- **Exact testable slice.** The project [documents](https://github.com/spring-petclinic/spring-petclinic-rest#-api-endpoints-overview) `POST /api/owners`, `POST /api/owners/{ownerId}/pets`, `POST /api/owners/{ownerId}/pets/{petId}/visits`, and corresponding `GET`, `PUT`, and `DELETE` routes. The machine-readable contract is [`src/main/resources/openapi.yml`](https://github.com/spring-petclinic/spring-petclinic-rest/blob/master/src/main/resources/openapi.yml); Swagger UI and the runtime OAS endpoint are also listed in the [README](https://github.com/spring-petclinic/spring-petclinic-rest#-openapi-rest-api-documentation).
- **Pipeline fit — assessment.** `context-marker` gets a strong mixed input: OpenAPI constraints, relational ownership, database profiles, and controller behavior. `tc-generator` can build owner → pet → visit chains plus invalid dates, missing parents, duplicate data, pagination, and CRUD boundaries. `tc-reviewer` can detect invented fields, wrong path nesting, missing negative cases, oracles that ignore generated error schemas, and cleanup in the wrong dependency order. Later auto-test-writer/reviewer work can compare generated-client or raw HTTP tests with the OpenAPI contract; full orchestration covers server startup, health checks, seeded H2 state, optional security configuration, and test isolation.
- **Windows setup and dependencies — Low.** The [README supports a single Docker command](https://github.com/spring-petclinic/spring-petclinic-rest#with-docker) or the Maven wrapper; [`mvnw.cmd`](https://github.com/spring-petclinic/spring-petclinic-rest/blob/master/mvnw.cmd) makes the latter Windows-native. The default profile is [an automatically seeded in-memory H2 database with no additional database setup](https://github.com/spring-petclinic/spring-petclinic-rest#database-configuration). Dependencies are therefore Docker Desktop alone, or a compatible JDK plus the project wrapper.
- **Proposed chain.** Start from the seeded reference data; create a unique owner; add a pet; add a visit; fetch the owner aggregate and verify the nested pet/visit; submit a future birth date and a missing-owner pet as negative cases; delete in reverse order. A second phase can enable the documented Basic-auth roles and prove `OWNER_ADMIN` versus `VET_ADMIN` authorization boundaries.
- **Caveat.** Authentication is [disabled by default and must be explicitly enabled](https://github.com/spring-petclinic/spring-petclinic-rest#security-configuration); the first campaign should either declare “security off” as a fixed precondition or enable it deliberately, never infer it from endpoint behavior.

### 3. Memos

- **Repository, stack, license, activity.** [Memos](https://github.com/usememos/memos) is a self-hosted note application with a Go backend and a React/TypeScript web package, as shown by the repository and [`web/package.json`](https://github.com/usememos/memos/blob/main/web/package.json). It supports SQLite, MySQL, and PostgreSQL and exposes REST/gRPC APIs according to its [README](https://github.com/usememos/memos#features). Its [license is MIT](https://github.com/usememos/memos/blob/main/LICENSE). The stable release selected here is [v0.29.1, released 2026-06-05](https://github.com/usememos/memos/releases/tag/v0.29.1).
- **Exact testable slice.** [`proto/api/v1/memo_service.proto`](https://github.com/usememos/memos/blob/main/proto/api/v1/memo_service.proto#L20-L111) maps creation to `POST /api/v1/memos`, listing and retrieval to `GET`, updates to `PATCH`, deletion to `DELETE`, and also defines comment, relation, reaction, and share operations. The same contract defines `PRIVATE`, `PROTECTED`, and `PUBLIC` [visibility values](https://github.com/usememos/memos/blob/main/proto/api/v1/memo_service.proto#L263-L269).
- **Pipeline fit — assessment.** `context-marker` must preserve user identity, visibility, resource-name syntax, pagination/filter semantics, and nested comment/reaction/share routes from protobuf and source. `tc-generator` can cover multi-actor visibility transitions and negative authorization as well as ordinary CRUD. `tc-reviewer` can catch the dangerous mistakes: treating protected as public, omitting actor changes, checking only success status, or failing to revoke a share. Later auto-test-writer/reviewer work gets stable JSON/gRPC-derived contracts; full orchestration adds first-user bootstrap, token capture, SQLite persistence, readiness, and per-run cleanup.
- **Windows setup and dependencies — Low.** The official [README documents a Docker launch and prebuilt binaries](https://github.com/usememos/memos#install-and-upgrade), and the [v0.29.1 release carries the pinned artifacts](https://github.com/usememos/memos/releases/tag/v0.29.1). A Docker-or-binary run can use SQLite, so the campaign needs only Docker Desktop or the Windows binary plus one writable data directory; it must still automate first-user creation and token acquisition.
- **Proposed chain.** Create users A and B; A creates a `PRIVATE` memo; B and anonymous callers cannot fetch it; A changes visibility or creates a share; B can then read and add a comment/reaction through the permitted path; A revokes access; B loses access; A deletes the memo.
- **Caveat.** Pin the stable tag and its protobuf contract: broad REST/gRPC, webhook, and streaming surfaces make “test Memos” too vague unless the memo-visibility chain is explicitly bounded.

### 4. Full Stack FastAPI Template

- **Repository, stack, license, activity.** [Full Stack FastAPI Template](https://github.com/fastapi/full-stack-fastapi-template) combines Python FastAPI, SQLModel/Pydantic, PostgreSQL, React/TypeScript/Vite, a generated frontend client, Playwright, and pytest; those components are enumerated in the [README](https://github.com/fastapi/full-stack-fastapi-template#technology-stack-and-features). Its [license is MIT](https://github.com/fastapi/full-stack-fastapi-template/blob/master/LICENSE). The checked-in [release notes record v0.10.0 on 2026-01-23](https://github.com/fastapi/full-stack-fastapi-template/blob/master/release-notes.md), including item/admin tests and authentication fixes.
- **Exact testable slice.** [`backend/app/api/routes/login.py`](https://github.com/fastapi/full-stack-fastapi-template/blob/master/backend/app/api/routes/login.py#L23-L47) implements the access-token login path and credential failures. [`backend/app/api/routes/items.py`](https://github.com/fastapi/full-stack-fastapi-template/blob/master/backend/app/api/routes/items.py#L15-L113) implements list/get/create/update/delete, owner filtering, superuser visibility, not-found behavior, and a `403` when a non-owner accesses an item. With the configured API prefix, the bounded public slice is `/api/v1/login/access-token` plus `/api/v1/items`.
- **Pipeline fit — assessment.** `context-marker` must reconcile route code, Pydantic/SQLModel schemas, JWT roles, environment configuration, generated client types, and UI flows. `tc-generator` can generate owner/non-owner/superuser matrices, CRUD boundaries, login failures, pagination, and password recovery. `tc-reviewer` can catch role confusion, missing token setup, mutable shared fixtures, and UI cases that assert navigation but not persisted API state. Later auto-test-writer/reviewer work can generate both API tests and Playwright tests against the same model; full orchestration has meaningful Compose readiness, migration, seed, mail-capture, logs, and cleanup steps.
- **Windows setup and dependencies — Medium.** The project’s [development guide uses `docker compose watch`](https://github.com/fastapi/full-stack-fastapi-template/blob/master/development.md), and its [Compose file](https://github.com/fastapi/full-stack-fastapi-template/blob/master/docker-compose.yml) defines the database and application services. Docker Desktop and changed development secrets are the practical baseline; native development additionally follows the Python and frontend tooling listed in the [development guide](https://github.com/fastapi/full-stack-fastapi-template/blob/master/development.md).
- **Proposed chain.** Use the initial superuser to create users A and B; log in as A; create and update an item; prove B receives `403`; prove the superuser can list the item; trigger password recovery and retrieve the message from the local mail-capture service; reset the password; delete the item and users.
- **Caveat.** This is a template, so the campaign must pin a commit/tag and retain its original example domain; customizing models before the baseline would confound skill quality with application-design changes.

### 5. Qdrant

- **Repository, stack, license, activity.** [Qdrant](https://github.com/qdrant/qdrant) is a Rust vector database with REST and gRPC interfaces; its Rust crate structure is visible in the repository’s [`Cargo.toml`](https://github.com/qdrant/qdrant/blob/master/Cargo.toml). Its [license is Apache-2.0](https://github.com/qdrant/qdrant/blob/master/LICENSE). The selected release is [v1.18.2, released 2026-06-04](https://github.com/qdrant/qdrant/releases/tag/v1.18.2).
- **Exact testable slice.** The official [`QUICK_START.md`](https://github.com/qdrant/qdrant/blob/master/docs/QUICK_START.md) supplies concrete REST calls to create a collection with vector size and distance, upsert points with payload, and run vector search with filters. The bounded campaign is: `PUT /collections/{name}`, `PUT /collections/{name}/points?wait=true`, filtered query/search, collection inspection, and deletion; no embedding model is required because fixed numeric vectors are valid inputs.
- **Pipeline fit — assessment.** `context-marker` must retain vector dimension, distance function, payload schema, filter grammar, eventual-operation/wait semantics, and error contracts. `tc-generator` gets strong numerical oracles, wrong-dimension/type boundaries, duplicate point IDs, filters, and lifecycle cases. `tc-reviewer` can reject vague “relevant result” assertions, float-order assumptions, missing wait/readiness, and collections not cleaned up. Later auto-test-writer/reviewer work can use raw REST or a generated OpenAPI client; full orchestration covers a container, health/readiness, deterministic seed vectors, collection namespacing, and teardown.
- **Windows setup and dependencies — Low–Medium.** The [quick start uses one Docker container exposing ports 6333 and 6334](https://github.com/qdrant/qdrant/blob/master/docs/QUICK_START.md); on Windows the practical dependency is Docker Desktop. Fixed four-dimensional vectors keep the campaign independent of Python ML packages, external model downloads, and GPUs.
- **Proposed chain.** Create `campaign_<run>` with vector size 4 and Dot distance; upsert three points with fixed vectors and `city` payloads using `wait=true`; query with a city filter and assert exact ID/order/score constraints; submit a three-dimensional vector and assert the documented error class; delete the collection.
- **Caveat.** The [quick start warns that the default Docker launch has no authentication or encryption](https://github.com/qdrant/qdrant/blob/master/docs/QUICK_START.md); bind the campaign only to localhost and never expose that container externally.

### 6. Mealie

- **Repository, stack, license, activity.** [Mealie](https://github.com/mealie-recipes/mealie) is a self-hosted recipe manager and meal planner with a Python backend and Vue/TypeScript frontend; the backend dependency set is in [`pyproject.toml`](https://github.com/mealie-recipes/mealie/blob/mealie-next/pyproject.toml) and the frontend stack is in [`frontend/package.json`](https://github.com/mealie-recipes/mealie/blob/mealie-next/frontend/package.json). Its [license is AGPL-3.0](https://github.com/mealie-recipes/mealie/blob/mealie-next/LICENSE). The selected stable release is [v3.22.0, released 2026-07-28](https://github.com/mealie-recipes/mealie/releases/tag/v3.22.0).
- **Exact testable slice.** The official [`recipe_crud_routes.py`](https://github.com/mealie-recipes/mealie/blob/mealie-next/mealie/routes/recipe/recipe_crud_routes.py) defines recipe listing/filtering, `GET /{slug}`, JSON creation with `201`, update, delete, duplicate, and multiple import routes. The bounded campaign should use direct JSON recipe CRUD and household access, not URL/image import, so expected data stays deterministic.
- **Pipeline fit — assessment.** `context-marker` must collect nested recipe schemas, slug-or-ID lookup, pagination/search filters, group/household identity, and error paths from a large route module. `tc-generator` can cover nested ingredients/instructions, slug changes, missing cookbook/recipe, pagination, and cross-household access. `tc-reviewer` can catch partial nested assertions, stale slugs after rename, absent household actors, and external-import dependencies masquerading as core coverage. Later auto-test-writer/reviewer work can combine API and Vue UI tests; full orchestration adds container readiness, initial admin/token setup, persistent data isolation, and cleanup.
- **Windows setup and dependencies — Medium.** The repository includes official [Docker build assets](https://github.com/mealie-recipes/mealie/tree/mealie-next/docker), and its [README describes easy Docker deployment](https://github.com/mealie-recipes/mealie#key-features). Docker Desktop plus a persistent data directory is the practical Windows route; the initial account and token remain campaign bootstrap work.
- **Proposed chain.** Authenticate an admin and create two household-scoped users; create a recipe with two ingredients and ordered instructions; fetch and filter it; update its name and nested data while tracking the resulting slug; prove the other household cannot mutate it; delete it and verify not-found.
- **Caveat.** Keep URL scraping, image recognition, and external AI providers out of the baseline: those routes exist in the [same official route module](https://github.com/mealie-recipes/mealie/blob/mealie-next/mealie/routes/recipe/recipe_crud_routes.py), but add network and provider variability unrelated to the skills under test.

### 7. Kanboard

- **Repository, stack, license, activity.** [Kanboard](https://github.com/kanboard/kanboard) is a PHP Kanban project-management application; its PHP package definition is [`composer.json`](https://github.com/kanboard/kanboard/blob/main/composer.json). Its [license is MIT](https://github.com/kanboard/kanboard/blob/main/LICENSE). The selected release is [v1.2.52, released 2026-04-05](https://github.com/kanboard/kanboard/releases/tag/v1.2.52).
- **Exact testable slice.** Kanboard’s server surface is JSON-RPC rather than ordinary REST. [`TaskProcedure.php`](https://github.com/kanboard/kanboard/blob/main/app/Api/Procedure/TaskProcedure.php) implements `createTask`, `getTask`, `getAllTasks`, `updateTask`, `moveTaskPosition`, `openTask`, `closeTask`, and `removeTask`, including project-permission checks. [`ProjectProcedure.php`](https://github.com/kanboard/kanboard/blob/main/app/Api/Procedure/ProjectProcedure.php) and [`CommentProcedure.php`](https://github.com/kanboard/kanboard/blob/main/app/Api/Procedure/CommentProcedure.php) provide the parent project and comment operations needed for a bounded chain.
- **Pipeline fit — assessment.** `context-marker` must preserve JSON-RPC envelope IDs, method names, positional/named parameters, boolean-versus-object results, authorization, and task state. `tc-generator` gains protocol-level invalid method/params cases plus project/task/comment lifecycle cases. `tc-reviewer` can catch REST assumptions, assertions that confuse `false` with transport failure, missing project permissions, and task cleanup without comment cleanup. Later auto-test-writer/reviewer work tests whether the generator remains protocol-neutral; full orchestration adds a container/PHP service, initial admin/API credentials, health polling, and data cleanup.
- **Windows setup and dependencies — Medium.** The official [README links the project’s Docker installation path and requirements](https://github.com/kanboard/kanboard#table-of-contents). Docker Desktop is the most practical Windows dependency; a native installation would instead require the PHP/web-server/extensions described by the project’s official documentation. The campaign must persist only the application data needed for the run and provision API credentials explicitly.
- **Proposed chain.** Authenticate to JSON-RPC; create a project; create a task in the first column; add a comment; move the task to another column; close and reopen it; prove a non-member cannot mutate it; remove the task and project; verify each response carries the matching RPC request ID.
- **Caveat.** The project explicitly states that it is [in maintenance mode, with small fixes and community-driven releases rather than major feature development](https://github.com/kanboard/kanboard#kanboard). That stability is useful for a fixture, but it lowers long-term priority.

### 8. Medusa

- **Repository, stack, license, activity.** [Medusa](https://github.com/medusajs/medusa) is a TypeScript/Node commerce framework; its monorepo metadata is in the root [`package.json`](https://github.com/medusajs/medusa/blob/develop/package.json). Its [license is MIT](https://github.com/medusajs/medusa/blob/develop/LICENSE). The selected release is [v2.15.3, released 2026-05-21](https://github.com/medusajs/medusa/releases/tag/v2.15.3).
- **Exact testable slice.** [`packages/medusa/src/api/store/carts/route.ts`](https://github.com/medusajs/medusa/blob/develop/packages/medusa/src/api/store/carts/route.ts) implements cart creation through the cart workflow. The [cart line-item route](https://github.com/medusajs/medusa/blob/develop/packages/medusa/src/api/store/carts/%5Bid%5D/line-items/route.ts) and [cart completion route](https://github.com/medusajs/medusa/blob/develop/packages/medusa/src/api/store/carts/%5Bid%5D/complete/route.ts) cover line mutation and completion, including concurrent-completion, validation, payment, and inventory failures. The bounded target is a pre-seeded product variant and one store-cart lifecycle.
- **Pipeline fit — assessment.** `context-marker` must join route handlers, workflow inputs, seeded catalog/sales-channel prerequisites, currency/region context, inventory, and error types. `tc-generator` can express empty-cart, invalid variant, quantity, stock, duplicate completion, and successful order cases. `tc-reviewer` can catch missing seed prerequisites, non-deterministic prices/stock, premature completion, and assertions that ignore the resulting order. Later auto-test-writer/reviewer work benefits from a TypeScript-native SDK/test stack; full orchestration must control PostgreSQL, migrations, seed, backend readiness, admin/store actors, and teardown.
- **Windows setup and dependencies — Medium–High.** The official [release stream documents `yarn dlx create-medusa-app@latest my-medusa-store` and the generated monorepo structure](https://github.com/medusajs/medusa/releases), while repository packages declare the Node/TypeScript environment. A reproducible Windows campaign should pin v2.15.3, use a supported Node/Yarn toolchain and PostgreSQL, and preserve its generated seed inputs rather than relying on an interactive `latest` scaffold.
- **Proposed chain.** Seed one region, sales channel, stock location, product, and variant; create a store cart; add the variant with quantity one; verify totals; attempt an invalid quantity or out-of-stock line; complete the valid cart; assert the returned order and that repeating completion cannot create a second order; clean up seeded data.
- **Caveat.** This is the first candidate where bootstrap and business prerequisites may dominate a short campaign. Run it only after the pipeline can report setup/readiness/seed failures separately from generated-test failures.

### 9. Keycloak

- **Repository, stack, license, activity.** [Keycloak](https://github.com/keycloak/keycloak) is a Java identity and access-management system with a Quarkus runtime and TypeScript web applications; the runtime is represented by [`quarkus/runtime/pom.xml`](https://github.com/keycloak/keycloak/blob/main/quarkus/runtime/pom.xml) and the repository’s JavaScript packages by [`js/package.json`](https://github.com/keycloak/keycloak/blob/main/js/package.json). Its [license is Apache-2.0](https://github.com/keycloak/keycloak/blob/main/LICENSE.txt). The selected release is [26.6.3, released 2026-06-04](https://github.com/keycloak/keycloak/releases/tag/26.6.3).
- **Exact testable slice.** [`RealmsAdminResource.java`](https://github.com/keycloak/keycloak/blob/main/services/src/main/java/org/keycloak/services/resources/admin/RealmsAdminResource.java) and [`UsersResource.java`](https://github.com/keycloak/keycloak/blob/main/services/src/main/java/org/keycloak/services/resources/admin/UsersResource.java) implement realm and user administration under the Admin REST surface. [`OIDCLoginProtocolService.java`](https://github.com/keycloak/keycloak/blob/main/services/src/main/java/org/keycloak/protocol/oidc/OIDCLoginProtocolService.java) defines the OpenID Connect protocol endpoints used for token acquisition and related flows. The bounded slice is one realm, confidential/public test client as appropriate, two users, one role, token/refresh, and disablement.
- **Pipeline fit — assessment.** `context-marker` must preserve bootstrap-admin versus realm-admin identity, realm/client/user IDs, credentials, role mappings, token endpoint form encoding, and claim expectations. `tc-generator` can derive login failures, role-positive/negative access, refresh, disabled-user, expired/invalid-token, and lifecycle cases. `tc-reviewer` can catch secret disclosure, mixed realms, assertions on unsigned decoded payload alone, absent cleanup, and role mappings applied to the wrong client. Later auto-test-writer/reviewer work exercises security-aware HTTP code and token handling; full orchestration adds server readiness, bootstrap credentials, realm import/setup, log capture, clock-sensitive assertions, and teardown.
- **Windows setup and dependencies — Medium.** The [README documents both `bin/kc.bat start-dev` and a container `start-dev` path](https://github.com/keycloak/keycloak#getting-started), and the official [Docker getting-started guide](https://github.com/keycloak/keycloak/blob/main/docs/guides/getting-started/getting-started-docker.adoc) provides the container bootstrap. The practical dependencies are either the pinned distribution plus a supported JDK, or Docker Desktop; the campaign also needs ephemeral bootstrap-admin credentials and deterministic realm/client creation.
- **Proposed chain.** Start dev mode with temporary bootstrap admin credentials; create realm `campaign`; create a client, users A/B, and role `editor`; assign the role only to A; obtain tokens; verify A’s claim and B’s missing role; refresh A’s token; disable A; prove a new login fails; remove the realm.
- **Caveat.** `start-dev` is deliberately a development configuration; treat it only as a localhost fixture. Pin 26.6.3 because its [release notes include security fixes](https://github.com/keycloak/keycloak/releases/tag/26.6.3), and never persist real credentials or production tokens in artifacts.

### 10. .NET eShop

- **Repository, stack, license, activity.** [.NET eShop](https://github.com/dotnet/eShop) is a C# reference e-commerce application using a services-based architecture and .NET Aspire, as stated in its [README](https://github.com/dotnet/eShop/blob/main/README.md). Current `main` pins [.NET SDK 10.0.100](https://github.com/dotnet/eShop/blob/main/global.json) and [Aspire 13.2](https://github.com/dotnet/eShop/blob/main/Directory.Packages.props). Its [license is MIT](https://github.com/dotnet/eShop/blob/main/LICENSE). The official [commit history records an API-versioning update on 2026-04-21 and an Aspire 13.2 update on 2026-03-24](https://github.com/dotnet/eShop/commits/main).
- **Exact testable slice.** [`CatalogApi.cs`](https://github.com/dotnet/eShop/blob/main/src/Catalog.API/Apis/CatalogApi.cs) maps `api/catalog` list/get, name/type/brand queries, and create/update/delete item routes. [`OrdersApi.cs`](https://github.com/dotnet/eShop/blob/main/src/Ordering.API/Apis/OrdersApi.cs) maps `api/orders` retrieval, draft/order creation, cancellation, and shipment operations; cancel/ship handlers include the request-ID input used for idempotent command processing. Begin with the catalog slice, then add basket/order/cancel only as an orchestration stretch.
- **Pipeline fit — assessment.** `context-marker` must distinguish services, route groups, seeded data, identities, synchronous REST results, async command behavior, and request IDs. `tc-generator` can cover catalog filters/CRUD, basket-to-order state, invalid IDs, and duplicate command IDs. `tc-reviewer` can catch cross-service setup gaps, eventual-state assertions made too early, missing idempotency checks, and cleanup that leaves messages or database state. Later auto-test-writer/reviewer work spans C# APIs and cross-service clients; full orchestration is the strongest candidate for Aspire startup, multiple containers, readiness dependencies, logs/traces, seeding, and coordinated teardown.
- **Windows setup and dependencies — High.** The official [README requires Docker Desktop and gives Windows startup paths plus `dotnet run --project src/eShop.AppHost/eShop.AppHost.csproj`](https://github.com/dotnet/eShop/blob/main/README.md#getting-started); current `main` requires the SDK selected by [`global.json`](https://github.com/dotnet/eShop/blob/main/global.json). Those prerequisites are Windows-friendly but materially heavier than a one-container fixture.
- **Proposed chain.** Start the AppHost and wait for the catalog service; query seeded items; create a uniquely named catalog item; update and filter it; delete it; then, in the stretch phase, add a seeded item to a basket, create an order, cancel it with a unique request ID, repeat the same command ID, and verify no duplicate transition.
- **Caveat.** Keep this tenth: it is valuable only when the orchestrator can attribute failures to AppHost, container, service readiness, data seed, test execution, or teardown rather than collapsing them into one generic FAIL. The [README still describes .NET 9](https://github.com/dotnet/eShop/blob/main/README.md#getting-started) while current [`global.json` selects .NET 10](https://github.com/dotnet/eShop/blob/main/global.json), so the campaign must trust pinned build files over stale prose.

### A. Gitea

- **Repository, stack, license, activity.** [Gitea](https://github.com/go-gitea/gitea) is a self-hosted Git forge written primarily in Go with web assets including TypeScript; its Go module is [`go.mod`](https://github.com/go-gitea/gitea/blob/main/go.mod) and frontend dependencies are in [`package.json`](https://github.com/go-gitea/gitea/blob/main/package.json). Its [license is MIT](https://github.com/go-gitea/gitea/blob/main/LICENSE). The selected release is [v1.26.2, released 2026-05-20](https://github.com/go-gitea/gitea/releases/tag/v1.26.2).
- **Exact testable slice.** The official [`routers/api/v1/api.go`](https://github.com/go-gitea/gitea/blob/main/routers/api/v1/api.go) carries the Swagger metadata and registers authenticated repository, issue, label, comment, and related API groups with token-scope and permission middleware; [`routers/web/web.go`](https://github.com/go-gitea/gitea/blob/main/routers/web/web.go) registers the Swagger UI route. Bound the campaign to creating a repository, creating/commenting/labeling/closing an issue, and a second user’s permission failure.
- **Pipeline fit — assessment.** This gives `context-marker` a large router plus Swagger, `tc-generator` multi-user repository/issue state, `tc-reviewer` scope/permission/cleanup traps, later auto-test-writer/reviewer a broad conventional REST API, and full orchestration a binary/container, initial admin, token provisioning, repository storage, and teardown.

Use a pinned Windows binary or Docker Desktop, an isolated data directory, and the simplest local database configuration documented by the repository; automate first-run admin and token creation.
- **Proposed chain.** Bootstrap admin and users A/B; A creates a private repository and token; A creates an issue, label, and comment, then closes it; B cannot read or mutate before membership and can after membership; A deletes the repository.
- **Caveat / why alternate.** It is an excellent general API target, but first-run configuration, token scopes, repository storage, and a very broad API make it less controlled than PocketBase or Memos for the first real-project campaign.

### B. Zulip

- **Pipeline fit — assessment.** `context-marker` must preserve realm/user/bot identity, stream/topic/message IDs, narrow filters, and event-like state. `tc-generator` can create multi-actor message/edit/reaction/permission chains; `tc-reviewer` can detect wrong actor, broad polling, missing event/result oracles, and non-idempotent cleanup. Later auto-test-writer/reviewer work gets a mature HTTP API, while full orchestration must handle multiple backing services, bootstrap, readiness, and eventual delivery.

### C. Apache Fineract

- **Repository, stack, license, activity.** [Apache Fineract](https://github.com/apache/fineract) is a Java/Spring core-banking platform built with Gradle and exposed through APIs, as described in its [README](https://github.com/apache/fineract/blob/develop/README.md). Its source distribution carries the [Apache-2.0 license text](https://github.com/apache/fineract/blob/develop/LICENSE_SOURCE). The selected release is [1.15.0, released 2026-07-14](https://github.com/apache/fineract/releases/tag/1.15.0).
- **Exact testable slice.** The quick start demonstrates an authenticated tenant-scoped request to `/fineract-provider/api/v1/clients` and documents the `Fineract-Platform-TenantId` header in the [README](https://github.com/apache/fineract/blob/develop/README.md#verify-the-application-is-running). [`LoansApiResource.java`](https://github.com/apache/fineract/blob/develop/fineract-provider/src/main/java/org/apache/fineract/portfolio/loanaccount/api/LoansApiResource.java) exposes loan creation and lifecycle commands. A bounded but rich slice is client creation followed by a preconfigured loan product’s application, approval, disbursement, repayment, and schedule/status retrieval.
- **Pipeline fit — assessment.** `context-marker` must capture tenant/auth headers, locale/date conventions, client/product prerequisites, command/action semantics, monetary schedules, and legal state transitions. `tc-generator` can derive invalid transition, amount/date boundary, duplicate-command, and repayment cases. `tc-reviewer` can catch financially weak oracles, missing product setup, forbidden transition order, wrong date formats, and cleanup that corrupts shared reference data. Later auto-test-writer/reviewer gets OpenAPI-backed Java REST coverage; full orchestration must manage PostgreSQL, migrations, TLS, tenant readiness, seed data, and teardown.
- **Windows setup and dependencies — High.** The [README requires a JDK and PostgreSQL, uses the Gradle wrapper, documents database creation and `devRun`, and exposes a readiness endpoint](https://github.com/apache/fineract/blob/develop/README.md#quick-start). On Windows, use `gradlew`/`gradlew.bat` with PostgreSQL in Docker or the project’s containerized development path; tests must account for the local self-signed HTTPS endpoint shown in the [README](https://github.com/apache/fineract/blob/develop/README.md#verify-the-application-is-running).
- **Proposed chain.** Authenticate to tenant `default`; create a unique client; use a pre-seeded loan product to submit a loan; prove repayment before approval/disbursement is rejected; approve and disburse on fixed dates; post a repayment; verify balances and schedule; close or remove only campaign-owned data through supported operations.
- **Caveat / why alternate.** It may be the strongest semantic/state-machine target, but its banking prerequisites and heavyweight setup would measure environment preparation more than portable skill behavior until orchestration is already mature.

## Рекомендуемый порядок кампаний

1. Start with **PocketBase** for the first end-to-end real-project smoke: the setup is smallest while auth, schema, filters, and ownership still expose weak context and case generation.
2. Run **Spring PetClinic REST** next to validate OpenAPI-grounded relational chains and generated error oracles, then **Qdrant** to prove the pipeline is not overfit to ordinary CRUD.
3. Add **Memos**, **Full Stack FastAPI Template**, and **Mealie** for multi-user authorization, nested models, generated clients, and API/UI expansion.
4. Use **Kanboard** as a protocol-neutrality gate before **Medusa** and **Keycloak**, whose workflows and security prerequisites require stronger reviewer discipline.
5. Reserve **.NET eShop** for full-orchestration acceptance. Promote Gitea, Zulip, or Fineract only when a ranked candidate is blocked or when the campaign explicitly needs their extra API breadth, event semantics, or financial state-machine depth.

## Общие ограничения и риски

- Release and default-branch links are a dated research snapshot. Before any campaign, pin a tag or commit and archive the exact API/spec files used as context; do not silently follow `latest`.
- “Windows-practical” does not mean “native-only.” Docker Desktop is the intended compatibility layer for several candidates; native-wrapper paths are called out where the repository provides them.
- Setup complexity is an estimate. A preflight should separately record download/build, service startup, readiness, bootstrap/seed, test execution, and teardown so infrastructure failures cannot be mis-scored as skill failures.
- Proposed chains intentionally avoid external email delivery, scraping, AI providers, cloud services, and nondeterministic third-party data. Local mail capture is acceptable only where the project already includes it.
- License compatibility for redistribution is outside this survey. Before artifacts leave a local campaign, review the pinned license for fixture redistribution, modified-image publication, and retained application data.
