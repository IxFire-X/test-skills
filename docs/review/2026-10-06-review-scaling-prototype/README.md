# Прототип компактного ревью (эксперимент 2026-10-06)

Только для замеров и как образец формата. Это не производственный код: в пакет переносится через план
`docs/superpowers/plans/2026-10-07-review-scaling.md` по правилам TDD.

- `projection.py` — текстовая проекция кейса с ID (шаги, входы, ожидания, проверки) и сигнатура возможности.
- `envelope.py` — один конверт ревью кейсов: SREQ дословно, CREQ и связь SREQ → CREQ, возможности, все кейсы.
  Режим `seeded` вносит 6 дефектов в `TCDOC-step5-java-demo-9340016c.r1.json`:
  S1 литерал проверки ≠ входу (TC-B1-005), S2 TC-B1-004 ждёт «Ramesh» вопреки SREQ-0006 и TC-B1-003,
  S3 текст DELETE «Student Deleted!», S4 список растёт после POST вопреки CREQ-B1-012,
  S5 неверный компонент TC-B1-010, S6 удалён единственный кейс GET /hello-world.
- `seed_automation.py` — один конверт ревью автотестов с 4 дефектами в `StudentControllerPipelineTest.java`:
  A1 404 вместо 400, A2 путь `/students/42`, A3 лишний `lastName: null`, A4 хелпер `fourStudents()` без четвёртого студента.
- `sim.py` — оценка числа частей при упаковке по кейсам (блоки и пары блоков) для step5 и Petclinic.
