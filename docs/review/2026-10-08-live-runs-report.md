### 3.2. Дефекты, исправленные в прогоне e

1. **`f395811` — блокировка прогона на Windows.** `pilot_state` держал `msvcrt.locking` байта 0 файла
   `.pilot-runs/<run>/.lock` на время команды драйвера, в том числе во время сборки проекта. Блокировки Windows
   обязательны: даже пустой файл с заблокированным байтом 0 не читается другим процессом. `nohttp-checkstyle` Petclinic
   читает `**/*` от `basedir`, сборка падала в `validate`, исполнение получало `GENERATED_TEST_INVALID` и тесты убирались.
   Теперь блокируется байт `0x7FFFFFF0` (за концом файла) — и в `model_runner._lock`. Тесты: удерживаемая блокировка
   прогона (другим процессом) и блокировка раннера ревью оставляют файл читаемым, второй владелец отклоняется.
2. **`0a9d96f` — длина команды Maven.** `-Dtest=<FQCN>#m1,<FQCN>#m2,…` для 81 метода — 8414 символов; `mvnw.cmd`
   выполняет cmd.exe (лимит 8191), тесты не запускались. Теперь методы одного класса — один шаблон Surefire
   `Класс#m1+m2` (тот же набор тестов; селектор целого класса не сливается), квитанции прежней формы проверяются.
   Живая проверка: 2726 символов, 81 тест.

Оба — с падающим тестом сначала, ревью старшей сессии до коммита; полный `ci_gate` на `0a9d96f` —
`D:\AI-Projects\windows-ci-gate-20261009-run-fg.log`.

## 5. Находки без исправления (этап 2 или решения пользователя)

1. Вывод упавшей сборки (`runner-output.txt` со строкой `[Help 1] http://cwiki…`) лежит в `.pilot-runs` и валит nohttp
   при любой следующей сборке проекта через жизненный цикл Maven: сломал U1 и сломает сборку проекта пользователем.
   Место хранения состояния прогона — решение пользователя.
2. Сбой фазы `validate` (окружение, сборка проекта) классифицирован как `GENERATED_TEST_INVALID` с предложением
   перегенерировать тесты.
3. Gradle на Windows (`gradlew.bat`, по `--tests` на селектор) упрётся в тот же лимит cmd.exe примерно на 90+ методах.
4. Группировка селекторов линейна по числу методов: класс на ~200+ методов снова упрётся в 8191 — делить исполнение
   на вызовы по бюджету строки или файл-список селекторов.
5. Разбор выживших — по одной группе на задачу (26 задач, 0,13–0,63 МБ входа каждая): 2,07 млн токенов — больше
   половины прогона.
6. Разборщику не показан полный код мутируемого класса и вызывающего кода: почти каждое решение EQUIVALENT опирается
   на знание Petclinic вне входа.
7. Задача `tc-generator:update` несёт весь документ набора (1,9 МБ) ради двух кейсов.
8. **Главная для этапа 2.** В `suite-update-v1` проверка ревьюера, ссылающаяся на неизменённые кейсы набора,
   незакрываема: план ревью обновления содержит только изменённые кейсы, область остаётся UNCHECKED, агрегат неполон
   (`review_blocked`), обновление не применяется. Нужно, чтобы план ревью обновления мог выдать часть проверки с
   неизменёнными кейсами набора как контекстом — как часть проверки полного ревью.
9. `pr-description.md` называет неполное ревью «блокирующими замечаниями» при 0 BLOCKING — формулировка должна
   говорить о неполном ревью и UNCHECKED-областях.

Находка № 1 повторилась в U1 и остановила прогон набора — второй аргумент за состояние прогона вне дерева проекта.

Из этапа 1 в отчёт без исправления: автоматизация одной задачей на весь документ (2,35 МБ; 0,25 млн токенов в e);
