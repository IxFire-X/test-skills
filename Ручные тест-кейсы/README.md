# tc-generator — Генератор ручных тест-кейсов

## Что это

AI-скилл, который автоматически генерирует ручные тест-кейсы на основе бизнес-требований (аналитики) и исходного кода. На выходе — структурированные тест-кейсы в формате Zephyr Markdown, готовые к передаче на валидацию или автоматизацию.

## Зачем нужен

Ручное написание тест-кейсов — долгий и трудоёмкий процесс. Скилл берёт на себя рутину: анализирует требования и код, покрывает основные сценарии (позитив, негатив, валидация, роли, наблюдаемость), следит за технической точностью (имена таблиц, коды ошибок, метрики — всё из реального кода, а не из головы).

## Как работает

Скилл работает в двух режимах:

- **Автоматический** — получает на вход аналитику и код в специальных тегах, сразу генерирует тест-кейсы
- **Ручной** — если данных нет, задаёт пользователю уточняющие вопросы, собирает контекст и только потом генерирует

Результат — блок `<generated_test_cases>` с тест-кейсами, который передаётся дальше по пайплайну.

## Что генерирует

- **Happy Path** — основной сценарий использования
- **Валидация** — обязательные поля, типы данных, граничные значения
- **Ролевая модель** — проверка прав доступа (если есть роли)
- **Негатив** — бизнес-ошибки и технические сбои
- **Наблюдаемость** — логи, метрики, аудит (если есть требования)

## Формат вывода

Тест-кейсы в формате Zephyr Markdown: заголовок, цель, предусловия, таблица шагов (действие → данные → ожидаемый результат). Каждый шаг детерминирован — один конкретный ожидаемый результат без «ИЛИ».

## Место в пайплайне

Первый этап. После него — `tc-reviewer` (валидация) или сразу `tc-to-autotest` (автоматизация).
