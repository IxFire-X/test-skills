как всё убрать после прогона.

## Сверка

Пакет — по списку сумм (из папки `kit/`):

```bash
sha256sum -c --quiet test-skills-9be8769.files.sha256    # молчит — все 318 файлов совпадают
```

Лишние файлы список не ловит; их ловит шаг 0 `operate.py` (`python3 operate.py … --only 0`): та же сверка плюс стоп,
если в `test-skills/` есть `.py`, которого нет в списке, и `doctor` пакета (целостность `release/manifest.json`).

Собственные файлы комплекта (`operate.py`, `preflight.py`, `wrap/`, `bench/`, документы — всё в `kit/` вне
`test-skills/`, кроме самого списка) — по `kit-files.sha256`:

```bash
sha256sum -c --quiet kit-files.sha256                    # молчит — все файлы комплекта совпадают
```

Список обновляется в том же коммите, что меняет файлы комплекта; он же закреплён коммитом ветки (сверка с
источником в клоне репозитория — `git diff --stat <коммит комплекта> -- kit/`). Шаг 2 перезаписывает
`wrap/wrap.json` под CLI компании (прежний — в `wrap/wrap.json.orig`), поэтому после него эта строка списка
расходится — так и должно быть.

## Что не поставляется и почему

| Не поставляется | Почему |
| --- | --- |
| `tests/` пакета (≈ 280 файлов) | тесты разработки пакета: при прогоне не нужны, в дереве проекта их фикстуры с `http://` ломают линтеры сборки (nohttp), а исполнять их у пользователя незачем |
| `docs/*.pptx` | презентации: не нужны для работы, тоже содержат `http://` |
| `CLAUDE.md`, `.claude/` | инструкции агенту разработки пакета: в дереве проекта модель могла бы принять их за инструкции проекта |
| `.github/` | CI репозитория пакета |

Тот же список исключений — в `test-skills/USAGE.md` (sparse checkout копии пакета).

### Почему в поставке evals/

`test-skills/evals/` — офлайн-оценки пакета: сценарии и результаты замеров ревью, «живого» набора и силы тестов,
снятые 2026-10-07/08 на открытом примере Spring Petclinic, с записанными ответами моделей по этим открытым данным
(часть данных — сжатые `*.json.gz`, читаются только скриптами оценок). Данных и файлов проекта компании в них нет:
оценки сняты до внутреннего прогона. При прогоне они не исполняются и в модель не уходят.

В поставке они потому, что входят в реестр целостности пакета: `release/manifest.json` перечисляет 53 файла `evals/`
с дайджестами, и без них `doctor` (шаг 0) сообщает о нарушении целостности. Вынос оценок из runtime-реестра — в
бэклоге пакета; после него `evals/` перейдёт в «не поставляется».

## Зависимости

- Python 3.11+ и `jsonschema`, `PyYAML` с транзитивными (`jsonschema-specifications`, `referencing`, `rpds-py`, `attrs`,
  `typing-extensions`) — версии и SHA-256 в `test-skills/requirements.txt`. Комплект ничего не ставит сам: при их
  отсутствии шаг 0 печатает команду `… -m pip install --require-hashes -r test-skills/requirements.txt` и
  останавливается. Если есть `test-skills/.venv`, пакет запускается его интерпретатором.
- JDK 17+ и сборка проекта (обёртка `mvnw`/`gradlew` или системный `mvn`), локальный репозиторий `~/.m2`.
- CLI модели компании (через `wrap/wrap.json`); учётные данные модели — в конфигурации самого CLI, комплект их не
  читает и не хранит.

Права, сеть и исполнение пакета подробно — `test-skills/USAGE.md`, раздел «Права, сеть и исполнение»; комплекта —
`RUN.md`, раздел «Права и сеть».

## Откат

Комплект ничего не устанавливает в систему. Чтобы убрать всё после прогона:

1. Удалить папку комплекта (`~/ts` или `<проект>/.ts`) — с ней уходят пакет, каталог раннера `<home>/runner`
   (`<home>/.runner`), состояние, журнал `operate.log` и отчёт `<home>/report/`. Если `--runner-dir` задавался
   отдельно — удалить и его.
2. В проекте: удалить `.pilot-runs/` и `test-cases/` (если набор не нужен); вернуть `.skillsrc` из копии
   `<home>/skillsrc.bak-<время>` (до шага 1) или удалить его, если его не было; сгенерированные тесты лежат только в
   тестовом корне модуля и видны в `git status` — откатить `git checkout -- <пути>` / `git clean` по ним. Прогон
   рекомендуется вести на отдельной ветке проекта: тогда откат проекта — удалить ветку.
3. Собранное сборкой (`target/`, `build/`, артефакты в `~/.m2`) — как после обычной сборки проекта.
