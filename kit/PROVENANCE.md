# Происхождение и состав поставки test-skills (хост-сборка для внутреннего прогона)

Для ревьюера: что это за папка, откуда она, как сверить её с источником, что в неё входит и что намеренно не входит,
как всё убрать после прогона.

Цепочка до `7d54c88` — S1–S11, P1–P2, D1a–D1c (как в универсальном комплекте `demo-kit-20261015`). Версия `0.5.0-pilot` (`test-skills/release/manifest.json`) |

Комплект ревьюится целиком: `kit/` — это и есть поставка. Пакет здесь уже распакован папкой: архивов в поставке нет,
распаковки (и, значит, zip-slip) при установке нет.

## Сверка

Пакет — по списку сумм (из папки `kit/`):

```bash
sha256sum -c --quiet test-skills-20c8cd4.files.sha256    # молчит — все 167 файлов совпадают
```

Лишние файлы список не ловит; их ловит шаг 0 `operate.py init`: та же сверка плюс стоп, если в `test-skills/` есть
`.py`, которого нет в списке, и `doctor` пакета (целостность `release/manifest.json` и профиль поставки: набор runtime-файлов
копии совпадает с профилем `host` в точности).

Собственные файлы комплекта (`operate.py`, `preflight.py`, `pack_query.py`, документы — всё в `kit/` вне `test-skills/`, кроме самого
списка) — по `kit-files.sha256`:

```bash
sha256sum -c --quiet kit-files.sha256                    # молчит — все файлы комплекта совпадают
```

Список обновляется в том же коммите, что меняет файлы комплекта; он же закреплён коммитом ветки (сверка с
источником в клоне репозитория — `git diff --stat <коммит комплекта> -- kit/`). Файлы, которые пишет `operate.py`
(`operate.log`, `init.json`, `agent-message.txt`, `report/` …), в список не входят.

## Состав поставки

| Путь | Что это | Исполняется? |
| --- | --- | --- |
| `test-skills/ts.py`, `test-skills/tools/` | пускатель и пакет: драйвер прогона, сканер проекта, адаптеры сборки (печатают команды сборки и тестов, сами их не запускают) | да — агент: только `ts.py next`/`submit`/`status`/`answer`/`doctor`; человек: `operate.py` |
| `test-skills/skills/`, `schemas/`, `contracts/`, `release/` | инструкции агенту (`skills/orchestrate/SKILL.md`) и ролям модели, JSON-схемы ответов, контракт пайплайна, манифест выпуска | нет — данные; SKILL.md читает агент |
| `test-skills/requirements.txt` | зависимости пакета с SHA-256 каждого файла (`pip install --require-hashes`) | ставит только человек |
| `test-skills/*.md`, `docs/examples/`, `docs/pilot-evidence.md`, `docs/portable-pipeline-overview-ru.md`, `docs/presentation-notes-ru.md`, `LICENSE`, `.skillsrc.example` | документация и примеры | нет |
| `operate.py` | инструмент человека: `init` до сессии агента (сверка, preflight, `.skillsrc`, замер без модели, первое сообщение агенту) и `report` после прогона; CLI и сборку не запускает | да — человек |
| `preflight.py` | проверка проекта до прогона (только чтение) | да — человек, через `init` |
| `pack_query.py` | вопрос `operate.py` к пакету только на чтение: модули `.skillsrc` пакетным парсером (`modules <.skillsrc>`, JSON на stdout); одна фиксированная подкоманда | да — человек, через `init` |
| `SKILL.md` | вход агента CLI: ссылка на `test-skills/skills/orchestrate/SKILL.md` и правила | нет — читает агент |
| `RUN.md`, этот файл | документация | нет |

Все процессы запускаются интерпретатором явно (`python3 operate.py`, `<интерпретатор> <пакет>/ts.py …`): ни один
скрипт не исполняется по shebang, `chmod +x` для файлов комплекта не нужен.

## Что не поставляется и почему

| Не поставляется | Почему |
| --- | --- |
| `tests/` пакета (≈ 280 файлов) | тесты разработки пакета: при прогоне не нужны, в дереве проекта их фикстуры с `http://` ломают линтеры сборки (nohttp), а исполнять их у пользователя незачем |
| `docs/*.pptx` | презентации: не нужны для работы, тоже содержат `http://` |
| `CLAUDE.md`, `.claude/` | инструкции агенту разработки пакета: в дереве проекта модель могла бы принять их за инструкции проекта |
| `.github/` | CI репозитория пакета |
| `tools/process_launch.py`, `tools/model_runner.py`, `tools/pipeline_driver_run.py`, `tools/pipeline_driver_runner.py`, `tools/company_runner.py`, `schemas/company-execution-receipt.schema.json` | запуск сборки, тестов и PIT пакетом и запуск CLI модели процессом: в хост-сборке их нет, а не выключены — драйвер без них отвечает `EXECUTION_MODE_UNAVAILABLE` / `RUNNER_UNAVAILABLE` |
| `skills/orchestrate/references/process-mode.md`, `manual-sequence.md`, `orchestration-contract.md` | инструкции процессного режима и ручной последовательности с запуском тестов пакетом |
| `tools/ci_gate.py`, `RELEASE.md`, `pytest.ini`, `requirements-dev.txt`, `evals/`, `docs/research/`, `docs/review/`, `docs/superpowers/`, прочие `docs/` | инструменты и материалы сопровождающего (CI, офлайн-оценки со сжатыми `*.json.gz`, исследования, ревью): при прогоне не нужны; `evals/` вне runtime-реестра хост-сборки |
| процессный режим: обёртка CLI `wrap/`, бенчмарк моделей `bench/`, `wrapper-contract.md`, `demo-script.md`, `docs/ustroystvo-test-skills.html`; в `operate.py` — шаги 2, 3, 5a, 5, 9 и проба CLI | в хост-сборке модель вызывает ведущая сессия CLI по команде человека, пакет и комплект CLI не запускают; всё это — в универсальном комплекте (`demo-kit-20261015`) |

Список исключений задан кодом пакета (`tools/release_manifest.py`: профиль `host`) и печатается командой из «Как собран
пакет»; описание — `test-skills/USAGE.md`.

## Зависимости

- Python 3.11+ и `jsonschema`, `PyYAML` с транзитивными (`jsonschema-specifications`, `referencing`, `rpds-py`, `attrs`,
  `typing-extensions`) — версии и SHA-256 в `test-skills/requirements.txt`. Комплект ничего не ставит сам: при их
  отсутствии шаг 0 печатает команду `… -m pip install --require-hashes -r test-skills/requirements.txt` и
  останавливается. Если есть `test-skills/.venv`, пакет запускается его интерпретатором.
- JDK 17+ и сборка проекта (обёртка `mvnw`/`gradlew` или системный `mvn`), локальный репозиторий `~/.m2`.
- CLI компании (`gigacode`) в интерактивной сессии с инструментом выполнения команд — запускает человек; учётные
  данные модели — в конфигурации самого CLI, комплект их не читает и не хранит.

Права, сеть и исполнение пакета подробно — `test-skills/USAGE.md`, раздел «Права, сеть и исполнение»; комплекта —
`RUN.md`, раздел «Права и сеть».

## Откат

Комплект ничего не устанавливает в систему. Чтобы убрать всё после прогона:

1. Удалить папку комплекта (`<проект>/.gigacode/skills/test-skills`) — с ней уходят пакет, состояние, журнал
   `operate.log` и отчёт `report/`; убрать её строку из `.git/info/exclude`.
2. В проекте: удалить `.pilot-runs/` и `test-cases/` (если набор не нужен); вернуть `.skillsrc` из копии
   `<home>/skillsrc.bak-<время>` (до `init`) или удалить его, если его создал `init`; сгенерированные тесты лежат только в
   тестовом корне модуля и видны в `git status` — откатить `git checkout -- <пути>` / `git clean` по ним. Прогон
   рекомендуется вести на отдельной ветке проекта: тогда откат проекта — удалить ветку.
3. Собранное сборкой (`target/`, `build/`, артефакты в `~/.m2`) — как после обычной сборки проекта.
