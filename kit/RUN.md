# Запуск test-skills на внутреннем проекте (хост-сборка: прогон ведёт агент CLI компании)

Комплект — папка `kit/` ветки `kit-host`, без архивов: `test-skills/` (пакет; без `tests/`, `docs/*.pptx`, `CLAUDE.md`,
`.github/`), `test-skills-*.files.sha256` (суммы его файлов), `operate.py`, `preflight.py`, `SKILL.md`, `PROVENANCE.md`,
этот файл. Прогон ведёт агент `gigacode` в вашей интерактивной сессии: он запускает только локальные команды пакета
(`next`/`submit`/`status`/`answer`/`doctor`), каждую задачу модели выполняет в своём окне (свежий субагент на задачу),
а сборку, тесты и мутации **вы** запускаете в своём терминале по командам, которые он покажет. В коде комплекта и пакета
нет сетевых вызовов и запуска CLI: модель вызывает ведущая сессия CLI по вашей команде.

`operate.py` — инструмент человека: `init` один раз до сессии агента и `report` после прогона. Агент его не вызывает.

## 0. Две проверки CLI (один раз, до всего)

Запустите `gigacode` интерактивно в папке проекта, как для работы, без `--approval-mode plan` и без правок настроек.

1. **Shell.** Агенту: «Выполни в терминале `python3 --version` и покажи вывод». Нужно: CLI спросил разрешение и
   выполнил. Запишите, что предлагает «разрешать всегда»: корень `python3` или всю команду.
   *Не прошла* (нет инструмента выполнения команд) — хост-сборка не работает: `/tools` (или `/help`) и вопрос
   платформе, выключен ли shell политикой. Дальше не идти.
2. **Свежий субагент.** «Запомни слово СЛИВА-42. Запусти субагента с заданием: назови кодовое слово, если знаешь;
   прочитай `pom.xml` и запиши его первую строку в файл `probe.txt` в корне проекта; верни одну строку "готово"».
   Нужно: субагент слова не знает, `probe.txt` записан, главный агент получил одну строку. Затем удалить `probe.txt`.
   *Не прошла* (субагентов нет или они видят контекст главного) — прогон возможен по запасному пути
   `orchestrate/SKILL.md`: агент выполняет задачи сам и просит вас очистить контекст (`/clear` или новая сессия) между
   задачами; ревью тогда честно помечается `SELF`. Это дольше и требует вашего участия на каждой задаче.

## Запуск: пять шагов

```bash
# 1. комплект — внутрь проекта, туда, где gigacode видит skills
mkdir -p <проект>/.gigacode/skills/test-skills && cp -r <комплект>/. <проект>/.gigacode/skills/test-skills/
echo '/.gigacode/skills/test-skills/' >> <проект>/.git/info/exclude
# 2. подготовка (venv пакета — если есть; иначе python3 с jsonschema и pyyaml)
cd <проект>/.gigacode/skills/test-skills && python3 operate.py init --project <проект> --docs <спека в проекте>
```

3. **Сессия агента.** `gigacode` в папке проекта; вставить сообщение, которое напечатал `init` (копия —
   `agent-message.txt` рядом с `operate.py`).
4. **По ходу прогона** агент останавливается и спрашивает вас:
   - **confirm-context** — какие файлы проекта уйдут в модель (список с размерами). Проверить и ответить агенту;
   - **approve-generated-tests** — какие тесты он записал в проект. Прочитать и ответить;
   - **human_exec** — команды сборки, тестов и мутаций. Выполнить их в своём терминале по порядку и дать агенту путь
     к отчёту (или код выхода и файл с выводом упавшей сборки).
5. **После прогона:** `python3 operate.py report --project <проект> --run <run_id>` — отчёт в `report/` и путь к CSV
   для Zephyr.

`init --profile cases-only-v1` — быстрая первая проверка: только кейсы и их ревью, без сборки. Обновление живого
набора — тоже через агента, профиль `suite-update-v1`.

## Разрешения в CLI

- Настройки CLI не править, режим «yolo» / автоодобрения не включать.
- «Разрешать всегда» — только для `… ts.py next`, `… ts.py submit`, `… ts.py status`.
- **Никогда** «всегда» для `… ts.py answer` (так отвечают гейты — их видите и подтверждаете вы) и для `python3`
  целиком (тогда агент без вас ответит гейт или запустит что угодно на Python).
- Любую другую команду агента (сборка, тесты, `cd`, удаление файлов) — отклонять: сборку и тесты запускаете вы сами.

## Поставка, раскладка, интерпретатор

Для ревью безопасности поставка — папка `kit/` целиком: происхождение, сверка (`sha256sum -c` по
`test-skills-*.files.sha256` и `kit-files.sha256`), что в поставке и чего нет, откат — `PROVENANCE.md`; описание в формате
протокола ревью — `SKILL.md`.

Комплект лежит **внутри проекта** (политика: запись вне проекта запрещена), в неотслеживаемой и исключённой из git
папке: `init` останавливается, если комплект вне `--project`, если его файлы отслеживаются git или папка не исключена
(тогда инвентарь пакета взял бы его в контекст модели). `--home` у `operate.py` по умолчанию — папка самого `operate.py`.

**Интерпретатор.** Пакет запускается Python'ом из `test-skills/.venv` (`bin/python`, на Windows `Scripts\python.exe`),
если такой venv есть, иначе тем, которым запущен `operate.py`; у него должны быть `jsonschema` и `pyyaml` — иначе `init`
останавливается с командой установки. Этот же интерпретатор (абсолютный путь) стоит в командах сообщения агенту —
системный `python3` без `jsonschema` агенту не годится. **Ни один скрипт не запускается по shebang**.

## Права и сеть

Что пакет читает, пишет и какие процессы запускает — `test-skills/USAGE.md`, «Права, сеть и исполнение». Коротко:

- **Модель.** Задачи (части спеки и кода проекта) читает агент CLI в своей сессии и отвечает моделью, настроенной в
  самом CLI. Пакет и комплект ничего не отправляют и CLI не запускают.
- **Сборка и тесты.** Пакет их не запускает (`execution.mode: human` в `.skillsrc`, пишет `init`): команды запускаете вы,
  в своём окружении. `init` пишет `modules[].test.offline: true` — команды идут с `-o` / `--offline`, только из `~/.m2`;
  `--online` — не включать offline.
- **Пины мутаций.** Jar'ы PIT и плагина-резолвера `maven-dependency-plugin` 3.8.1 закреплены по SHA-256
  (`test-skills/tools/mutation_tools.json`); preflight проверяет их и `junit-platform-launcher` в `~/.m2`. Нет —
  мутаций в прогоне не будет (в сообщении агенту — без `--mutation`, с причиной).
- **pip.** `operate.py` ничего не ставит: без `jsonschema`/`pyyaml` печатает
  `pip install --require-hashes -r test-skills/requirements.txt` и останавливается.
- **`operate.py` и `preflight.py`** в сеть не ходят. Пишут в папку комплекта (`operate.log` — хвосты вывода по 200
  строк, похожие на секреты значения замаскированы; `init.json`, `agent-message.txt`, `context-files.txt`,
  `preflight.json`, `report/`), а в проект — только `.skillsrc` (после diff и подтверждения) и `chmod +x mvnw/gradlew`
  (с подтверждением). `--yes` эти два подтверждения не снимает — для них `--yes-skillsrc` и `--yes-chmod`.
- **Линтеры по всему дереву** (nohttp, checkstyle, spotless …): preflight печатает строку excludes для `.pilot-runs` и
  папки комплекта — вставить на ветке прогона, иначе сборка упадёт на файлах прогона.

## init подробно

```bash
python3 operate.py init --project <проект> --docs <спека в проекте> [--target <каталог фичи>] [--module <id>] \
  [--profile local-pilot-v1|cases-only-v1] [--model <модель CLI>] [--no-mutation] [--online]
```

По очереди:

1. **Место комплекта** — внутри проекта, не отслеживается git, исключён (`.git/info/exclude` или `.gitignore`).
2. **Шаг 0** — сверка `test-skills/` с `test-skills-*.files.sha256` (лишние `.py` — тоже стоп), Python 3.11+,
   `jsonschema`/`pyyaml`, `doctor` пакета.
3. **Шаг 1, preflight** — JDK, сборка, `~/.m2`, PIT, линтеры, ПДн/секреты в файлах, которые уйдут в модель. «Стоп» —
   остановка с подсказкой (в `cases-only-v1` — только список «до сборки»); неисполняемый `mvnw` — `chmod +x` после
   подтверждения.
4. **`.skillsrc`** — если его нет, пакет предлагает модули (`tools.init_skillsrc`), после подтверждения создаёт; вопросы
   пакета — стоп с командой ответа.
5. **Модуль и `--target`** — модуль по `.skillsrc` (несколько — тот, где спека); не влезает в порог задачи — `--target`
   угадывается по словам спеки или показываются до 5 каталогов-кандидатов.
6. **Шаг 4, правки `.skillsrc`** с diff и подтверждением (`--yes-skillsrc`): `requirements.id_pattern` (выводится из
   спеки, `--id-pattern`), `mutation.enabled` (если PIT найден), `modules[].test.offline: true`, системный `mvn` вместо
   отсутствующей обёртки, `limits.task_input_bytes` (700 000 или 0,8 окна, что меньше; `--task-input-bytes`),
   `execution.mode: human`; блок `review_runner` удаляется (процессного раннера в этой сборке нет). Прежний `.skillsrc` —
   в `skillsrc.bak-*`.
7. **Замер первой задачи без модели** — `next` драйвера во временном прогоне: список файлов для модели с размерами
   (копия — `context-files.txt`) и оценка в байтах и токенах против порога. Больше — стоп с подсказкой `--target`;
   файлы комплекта в списке — стоп. `confirm-context` `init` не отвечает: это сделаете вы в сессии агента. Временный
   прогон удаляется по своему `run_id` (только он, только в `.pilot-runs`); `init` печатает, что `.pilot-runs` и
   `git status` проекта остались как были.
8. **Первое сообщение агенту** — экран и `agent-message.txt`: путь к `test-skills/skills/orchestrate/SKILL.md`, форма
   команд (`<интерпретатор> <пакет>/ts.py next|submit|status|answer|doctor …`), первая команда `next … --compact` с
   проектом, модулем, спекой, `--target`, профилем (`--mutation` — только если PIT найден и `mutation.enabled: true`),
   как продолжить после перерыва (`status`, затем `next --run <run_id> --compact`), правила (human_exec и гейты — только
   человек). В конце — что ещё спросит прогон и что нужно до сборки.

### Арифметика контекста

Замер внутреннего прогона 2026-10-15 (DeepSeek-V4.1-Flash через gigacode): 0,24 токена на байт входа, жёсткий лимит
239 144 токена ≈ 1 000 000 Б. В хосте задача модели идёт в окне субагента вместе с системным промптом CLI, описаниями
инструментов, SKILL роли и ответом — поэтому порог задачи 700 000 Б (`limits.task_input_bytes`). Задача разметки модуля
`main` (377 файлов, 3 МБ инвентаря) дала 1 352 513 Б — `--target <каталог фичи>` обязателен для проектов больше
одного модуля или ~0,7 МБ кода; `--module` — при нескольких модулях. Другая модель — `--tokens-per-byte`,
`--model-context`.

## report

```bash
python3 operate.py report --project <проект> --run <run_id> [--only 7|8]
```

Итог берётся из `status` драйвера (только чтение: незаконченный прогон `report` не продвигает и останавливается «прогон
не закончен»). Без `--run` — последний прогон в `.pilot-runs` с подтверждением.

- **7** — `report/`: `driver-log.jsonl`, `config.json` (без секретов), `run-result.json`, `errors.txt`, строки ошибок
  Maven из `runner-output.txt`, `test-strength.md`, `summary.md` (итог, кейсы, покрытие дизайна и приоритеты, части
  ревью, тесты, мутанты, режим исполнения, время `init`).
- **8** — путь к CSV для Zephyr и его первые строки.

## Если остановился

| Что | Что делать |
| --- | --- |
| `init`: «СТОП … Что делать: …» | исправить сказанное и выполнить готовую команду из строки |
| агент: `ask_user` `confirm-context` | открыть список файлов; лишнее — исключить (`--target`, `paths` модуля, `.gitignore`), заново `init` и новый прогон; всё верно — ответить агенту «подтверждаю» |
| агент: `ask_user` `approve-generated-tests` | прочитать файлы; одобрить или остановить прогон |
| агент: `human_exec` | выполнить команды по порядку в указанных `cwd`; дать агенту путь к отчёту JUnit (мутации — что команда записала; упавшая сборка — код выхода и файл с её выводом); `HUMAN_REPORT_INVALID` — отчёт не новый или не из указанного каталога |
| `TASK_INPUT_TOO_LARGE` | задача больше порога, модель не вызывалась: новый прогон с более узким `--target` (`init --target …`) |
| `RUNNER_UNAVAILABLE` / `EXECUTION_MODE_UNAVAILABLE` | в `.skillsrc` или команде — процессный раннер / `execution.mode: auto`: в хост-сборке их нет; повторить `init` (уберёт) |
| `"action": "error"`, `code` | код и `message` — в отчёт; `DRIVER_FAILURE` — дефект пакета |
| `completion: PARTIAL`, `reason_code` | `reason_code` — в отчёт |
| verification `FAIL` | ожидаемо при дефекте продукта: `quarantine.md` (вопрос аналитику и черновик баг-репорта) |

## Что принести

Папку `report/` после `report` (шаг 7): журнал драйвера, конфиг без секретов, итог, коды и тексты ошибок, строки ошибок
Maven (без кода проекта), `test-strength.md`, `summary.md`. Не приносить: код, спеку, кейсы, ответы модели.

## Zephyr

Импортировать `test-cases/test-cases.zephyr-scale.csv` (не XML). Приоритеты в экспорте — High / Normal / Low.
Обязательные пользовательские поля Zephyr (АС, Вид тестирования, Команда, Приоритет теста) проверить в первой строке
перед массовым импортом.

## Откат

`PROVENANCE.md`, «Откат»: удалить папку комплекта, в проекте — `.pilot-runs/`, `test-cases/`, сгенерированные тесты
(видны в `git status`), вернуть `.skillsrc` из `skillsrc.bak-*`, убрать строку из `.git/info/exclude`.
