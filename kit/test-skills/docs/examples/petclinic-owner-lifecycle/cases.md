## ТК-1. Создание карточки владельца с сохранением пяти полей

**Цель:** Проверить переход от формы к новой карточке без потери контактов.

**Предусловия:**
- Доступна отдельная исходная база клиники с начальными данными. Владелец — человек, которому принадлежат питомцы; визит относится к конкретному питомцу. Данные сценария создаются в указанных ниже шагах.

**Шаги:**

### Шаг 1

Получить список владельцев, уже существующих в исходной базе клиники, и зафиксировать их количество.

**Тестовые данные / запрос**

Исходная база клиники с начальными данными, указанная в предусловиях.

**Ожидаемый результат**

Зафиксированы записи всех владельцев исходной базы и их количество для сравнения после действий сценария.

### Шаг 2

Открыть форму создания владельца: GET /owners/new.

**Тестовые данные / запрос**

Параметры отсутствуют.

**Ожидаемый результат**

Форма создания показывает имя, фамилию, адрес, город и телефон.

### Шаг 3

Создать владельца: POST /owners/new.

**Тестовые данные / запрос**

firstName="Anna"; lastName="PilotLifecycle"; address="10 Test Street"; city="Testville"; telephone="0123456789"

**Ожидаемый результат**

Создан владелец с выданным ID; ответ перенаправляет на его карточку.

### Шаг 4

Заново открыть карточку владельца и сверить сохранённые данные.

**Тестовые данные / запрос**

ID владельца получен в предыдущем шаге создания; наблюдать его контакты, питомцев и визиты.

Владелец в адресе: ID из шага 3.

**Ожидаемый результат**

Карточка показывает Anna PilotLifecycle, 10 Test Street, Testville, 0123456789 с исходным нулём; питомцев нет. ID совпадает с выданным, владелец добавлен ровно один.

### Шаг 5

Сравнить количество сохранённых владельцев с исходным.

**Тестовые данные / запрос**

Владельцы до отправки формы и после нового чтения.

**Ожидаемый результат**

Количество владельцев изменилось на 1.
